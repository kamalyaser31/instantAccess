# Plan: instantAccess 2026.8, conditions (if and else)

Status: deferred by Kamal on 2026-11-07, until a real need appears. If one does, first try a small version: one optional "run only if" field per action, with three or four conditions, no Else and no nesting.

## Goal

An item can choose what to do while it runs. Example: if the clipboard has text, search for it; otherwise, read the selected text.

## Decisions from Kamal (2026-11-07)

- Full if and else, not only skipping one action.
- Conditions are flexible: several kinds, which can be combined.
- The user picks from lists and never types a formula, because written formulas are hard for users.
- It ships in 2026.8, after 2026.7.

## Proposed design

- **A flat list, not a tree.** Three new action types sit in the item's actions list: **If**, **Else** and **End if**. A flat list is easy with a screen reader, and existing buttons (Add, Move up, Move down, Delete) keep working. The list's Details column says the condition in words, and a nested action says its depth, such as "inside If".
- **One condition is one row of three fields:** what to check, how to compare, and a value when needed.
  - Selected text, Clipboard: has text, is empty, contains, is exactly.
  - Current app: is one of (comma list).
  - File or folder: exists.
  - Program: is running.
  - Time: is between two times.
  - Day: is one of the days of the week.
  - Previous action: succeeded, failed.
- **Combining:** one If can hold several conditions, joined by **All of these** or **Any of these**, and each condition can be negated with a **Not** checkbox.
- **Nesting:** an If may sit inside another If. An item with an unmatched If, Else or End if can't be saved, and the error names the problem.

## Effects on existing features

- **Saved items:** old configs keep working, and the new types are stored with the existing action format.
- **Stop on error:** a condition that is false is not an error. A failed action inside a branch follows the item's setting.
- **Interval:** runs between actions that actually run, not skipped ones.
- **Selected text and File Explorer:** a condition that reads them joins `itemNeedsContext`, so the values are read once when the item starts.
- **Test button:** in the item dialog, If, Else and End if can't be tested alone. Testing the item runs the whole logic.
- **Import:** a file from a newer version with unknown action types is refused, as it is today.

## Milestones

- **M1:** Evaluate conditions in a new module without NVDA or wx (`conditions.py`), with tests.
- **M2:** Run If, Else and End if in `executeInstantItem`, with validation, nesting and tests.
- **M3:** The condition dialog and the list wording. Self-audit the tab order and labels.
